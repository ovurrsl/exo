## The spec question

Anthropic's Messages API does not accept `"system"` inside `messages`; it has a
top-level `system` parameter instead. So this PR makes exo deliberately more
permissive than the API it emulates. That is defensible — clients in the wild do
send it, which is the whole reason #2193 exists — but it is a decision, and the
PR presents it as a bug fix.

The two readings, and they lead to different code:

- **Compatibility shim.** Accept it, hoist it, move on. That is this PR. If so,
  the description should say "deliberately more lenient than upstream" so nobody
  later removes it as a spec violation.
- **Strict emulation.** Keep rejecting, but return a 400 with a message that
  names the top-level `system` parameter instead of a raw pydantic 422. Less
  useful to the user in #2193, more faithful.

I lean toward the first, because a local inference server's job is to be easy to
point existing tooling at. But a maintainer should pick, and right now the PR
does not surface that there is a choice.
