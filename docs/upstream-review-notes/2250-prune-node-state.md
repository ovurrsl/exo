## The completeness argument

I think this is worth stating in the PR description, because it turns "two more
dict comprehensions" into "an invariant is now closed". `State` has eleven
`Mapping[NodeId, ...]` fields:

```
downloads, last_seen, node_identities, node_memory, node_disk, node_system,
node_network, node_thunderbolt, node_thunderbolt_bridge, node_rdma_ctl,
node_backends
```

On `main`, `apply_node_timed_out` prunes nine of them. The two it misses are
`node_identities` and `node_backends` — exactly the two this PR adds. After this
PR all eleven are pruned, so there is no remaining per-node map that outlives the
node. That also means the omission was almost certainly an oversight when those
two fields were introduced, not a deliberate retention policy.

## One thing a maintainer will want to confirm

`node_identities` is what the dashboard reads for friendly names. Dropping the
entry means a node that times out mid-render loses its display name rather than
showing as a greyed-out "last known" entry. If keeping the name for disconnected
nodes was intentional, the fix belongs at the render layer instead, and this PR
would be wrong. Nothing in the code suggests that was intentional — the other
nine maps are already dropped, so a timed-out node already has no memory, disk,
or network entry to render either — but it is the only judgement call in the
diff and it is worth a sentence in the description.

Beyond that the diff is mechanical and matches the style of the nine existing
comprehensions exactly.
