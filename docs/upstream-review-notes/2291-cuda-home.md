## Two implementation notes

`CUDA_HOME` is set to the `cuda_runtime` directory, which the pip wheel populates
with `include/` and `lib/` but not `bin/nvcc`. That is enough for NVRTC, which is
what the docstring describes. If anything downstream ever shells out to `nvcc`
under the same `CUDA_HOME`, it will not find it. Probably fine, and probably worth
one line in the docstring so the next person does not widen this function by
accident.

The loop takes the first `submodule_search_locations` entry that has an
`include/` directory. With a single `nvidia` wheel set installed that is
unambiguous. In a layered environment (system site-packages plus a venv) the
order is whatever the namespace package finder returns. Not worth engineering
around, but `logger.info` already records the chosen path, which is the right
mitigation.

Setting a process-wide environment variable from inside the runner entrypoint is
mildly surprising, but the entrypoint runs in a dedicated subprocess, so the
mutation cannot leak into the parent. That is the correct place for it.
